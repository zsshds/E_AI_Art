## Why

当前系统默认将文生图/编辑图任务提交到固定路径 `/v1/images/generations/tasks`，当切换到不同第三方 API 平台时，平台的接口组织方式可能不同，导致请求直接返回 404。现有系统设置仅支持少量接口参数，无法覆盖文生图、编辑图、轮询、模型列表、聊天补全等完整链路，也无法让不同平台按各自接口结构灵活适配。

为了降低切换第三方平台的接入成本，需要把图像相关接口配置从“少量固定字段”扩展为“全链路可配置”，并支持“相对 Path”与“完整 URL”两种配置方式，使管理员可以在系统设置中直接调整接口，而无需改代码或重启服务。

## What Changes

- 扩展系统设置页，新增图像相关接口配置项，覆盖文生图、编辑图、任务轮询、模型列表、聊天补全等调用链路。
- 后端图像客户端按设置动态解析各接口地址，支持每项配置填写相对 Path 或完整 URL。
- 将文生图与编辑图的提交接口解耦，允许不同第三方平台分别配置。
- 为缺省配置和未填写场景定义清晰的回退行为，保证已有部署在未迁移全部配置前仍能工作，或返回明确错误。
- 补充与接口解析、设置保存、关键调用路径相关的测试，覆盖典型第三方平台适配场景。

## Capabilities

### New Capabilities
- `image-api-endpoint-config`: 允许管理员在系统设置中配置图像相关各类接口端点，并在运行时动态生效。

### Modified Capabilities
- 无

## Impact

- 后端：`backend/internal/service/image/client.go` 的接口解析与请求构造逻辑。
- 后端：系统设置读写与默认值初始化，如 `backend/internal/handler/setting.go`、`backend/cmd/server/main.go`。
- 前端：系统设置页与设置 API 类型定义，如 `frontend/src/views/SettingsPage.vue`、`frontend/src/api/setting.ts`。
- 测试：图像客户端、设置处理器及相关回归测试需要覆盖新增配置项与 URL 解析行为。
- 运维：已有环境的默认配置与迁移体验会受到影响，需要兼容当前字段或提供平滑回退。
